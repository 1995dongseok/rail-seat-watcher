# 빈자리 알리미 (rail-seat-watcher)

기차 잔여석(코레일)과 공연 취소표(NOL 티켓, 구 인터파크)를 조회하고, 빈자리가 생기면 텔레그램으로 알려주는 소수 지인용 웹 앱입니다. 화면은 **기차 / 공연** 탭으로 나뉩니다.

- 사용자마다 앱 계정을 만들고(초대코드 필요), 각자 텔레그램을 연결합니다. 코레일 계정은 기차 조회에만 필요합니다.
- 조회: 출발역/도착역(드롭다운), 날짜, 시간 범위(또는 하루 전체), 열차 종류. 왕복이면 가는 편·오는 편을 동시에 조회. 조회 결과(빈자리 열차 목록)는 즉시 텔레그램으로도 전송
- 감시: 조건을 등록하면 주기적으로 조회해 매진 → 가능 으로 바뀐 열차를 등록한 사람의 텔레그램으로 알림
- 공연(NOL 티켓): 지금 판매 중인 공연을 공연명·아티스트·장르로 검색해 관람일별 회차·등급 잔여석을 조회하고, 감시를 등록하면 취소표가 생겼을 때 알림. 계정 등록이 필요 없습니다.

## 주의

- 코레일 공식 API가 아니라 코레일 앱 API를 감싼 비공식 라이브러리(pykorail)를 사용합니다. 코레일이 앱을 바꾸면 예고 없이 멈출 수 있습니다.
- 공연 조회도 NOL 웹이 쓰는 비공개 JSON 엔드포인트를 그대로 호출합니다(로그인 없음). NOL 은 매크로 등 비정상 접근을 제재 대상으로 명시하므로 조회만 하고 예매는 직접 하세요. 엔드포인트가 바뀌면 멈춥니다.
- 코레일 이용약관은 자동화 도구 사용을 제한합니다. 모든 사용자의 요청이 서버 한 곳에서 나가므로 사용자와 감시 건수가 늘수록 조회 주기를 넉넉히 잡으세요. 서버는 코레일 호출을 한 번에 하나씩만 보내고 감시 건 사이에 3초를 쉽니다.
- 코레일 비밀번호는 `data/secret.key` 로 암호화해 `data/users.json` 에 저장합니다. `data/` 폴더와 `.env` 는 공유하거나 커밋하지 마세요. `secret.key` 를 잃으면 사용자들이 코레일 비밀번호를 다시 입력해야 합니다.
- 통신은 HTTP 입니다. 집이나 사무실 같은 신뢰할 수 있는 네트워크 안에서만 쓰세요. 외부 공개는 권하지 않습니다.

## 설치

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
```

`.env` 를 열어 값을 채웁니다.

| 항목 | 설명 |
|---|---|
| `TELEGRAM_BOT_TOKEN` | @BotFather 에서 만든 봇 토큰. 서버에 하나만 둡니다 |
| `INVITE_CODE` | 가입 초대코드. 지인에게 알려 주면 가입할 수 있습니다 |
| `POLL_INTERVAL_SEC` | 새 사용자의 기본 감시 주기(초). 최소 30. 사용자별 주기는 관리자 페이지에서 따로 정합니다 |
| `HOST` | 같은 네트워크의 다른 기기에서 접속하려면 `0.0.0.0` |

## 실행

```powershell
.\venv\Scripts\python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

브라우저에서 http://127.0.0.1:8000 을 엽니다. 다른 기기에서 접속하려면 `--host 0.0.0.0` 으로 띄우고 서버 PC 의 IP 로 접속합니다.

## 관리자

- `.env` 의 `ADMIN_USERNAME`(기본 `admin`) 이름으로 가입한 계정이 관리자입니다. 관리자는 항상 사용 허용 상태입니다.
- 신규 가입자는 **기본 거부** 상태라 조회·감시 버튼이 비활성화되고 서버도 요청을 거부합니다. 관리자가 `/admin` 에서 **허용**을 눌러야 사용할 수 있습니다.
- 텔레그램은 사용자가 "내 설정"의 6자리 연결 코드를 봇에게 보내면 서버가 자동으로 chat_id 를 연결합니다. 관리자는 `/admin` 에서 연결 상태를 보고 필요하면 chat_id 를 직접 고칠 수 있습니다.
- 서버가 봇의 getUpdates 를 계속 읽고 있으므로, 브라우저에서 getUpdates 주소를 직접 열면 서로 충돌합니다(409). 수동 확인은 더 이상 필요 없습니다.
- 관리자는 사용자를 삭제할 수 있고, 삭제하면 그 사용자의 감시도 함께 지워집니다.
- **감시 상한**: 사용자당 동시에 활성화할 수 있는 감시는 기차 2건, 공연 2건이 기본입니다(중지·종료된 감시는 제외, 종류별로 따로 셉니다). 왕복 등록은 기차 2건을 씁니다. 관리자는 `/admin` 에서 사용자별로 기차·공연 상한(0~20)을 각각 조정할 수 있고, 관리자 본인은 무제한입니다. 상한을 넘기는 등록과 재개는 서버가 거부합니다.
- **감시 주기**: 사용자마다 다르게 둘 수 있습니다(30~3600초, 기본은 `.env` 의 `POLL_INTERVAL_SEC`). 감시 루프는 10초마다 깨어나 "마지막 점검 + 그 사용자의 주기"가 지난 감시만 점검합니다.
- **부하 게이지**: `/admin` 상단에 코레일(기차, 상한 30회/분)과 NOL 티켓(공연, 상한 60회/분) 게이지가 따로 있습니다. 활성 감시가 각자 주기로 돌 때 나가는 호출을 계산한 값으로, 상한을 넘으면 빨간색이 됩니다. 실측(최근 10분) 값과 사용자별 기차·공연 감시 수도 함께 보여 줍니다. 넘으면 주기를 늘리거나 감시 상한을 줄이세요.
- **누적 조회**: 사용자 표의 "누적 조회" 열에 그 사람이 지금까지 실제로 내보낸 코레일·NOL 호출 수(감시 점검 + 수동 조회 모두 포함)가 서버 재시작과 무관하게 계속 쌓입니다(`data/call_stats.json`). 사용자를 삭제하면 그 값도 함께 지워집니다.

## 사용 방법 (튜토리얼)

처음 쓰는 분은 1번부터 순서대로 따라 하면 5분이면 끝납니다.

### 1. 가입하기

1. 로그인 화면에서 **가입** 탭을 누릅니다.
2. 사용자명(2~20자), 비밀번호(4자 이상), 관리자에게 받은 **초대코드**를 입력합니다.
3. **가입하고 시작**을 누르면 바로 로그인됩니다.

> 여기서 만드는 계정은 이 사이트 전용입니다. 코레일 계정과는 별개이며, 비밀번호도 다르게 정해도 됩니다.

### 2. 코레일 계정 등록 (기차만)

기차 조회는 본인의 코레일 계정으로 이루어집니다. 공연 취소표만 쓸 거라면 이 단계는 건너뛰어도 됩니다. 코레일톡 앱이나 letskorail 에서 쓰는 로그인 정보를 그대로 넣으면 됩니다.

1. 조회 화면 상단의 **내 설정**을 펼칩니다. 처음에는 자동으로 펼쳐져 있습니다.
2. 코레일 아이디(이메일, 휴대폰번호, 회원번호 중 하나)와 비밀번호를 입력하고 **저장**.
3. 관리자 승인 후 **코레일 로그인 테스트**를 눌러 "로그인 성공"이 뜨는지 확인합니다.

> 비밀번호는 서버에 암호화되어 저장되고 화면에 다시 표시되지 않습니다. 바꾸고 싶을 때만 새로 입력하면 됩니다.

### 3. 텔레그램 연결

알림은 텔레그램으로 옵니다. 텔레그램 앱이 없다면 먼저 설치하고 계정을 만들어 주세요.

1. **내 설정** 아래쪽 **텔레그램 알림** 항목에 6자리 **연결 코드**가 보입니다.
2. 그 옆의 봇 이름을 누르면 텔레그램에서 봇 대화창이 열립니다. 휴대폰이면 텔레그램 앱에서 봇 이름을 검색해도 됩니다.
3. 대화창에서 **시작**을 누르거나 아무 말이나 보낸 뒤, **연결 코드 6자리**를 보냅니다.
4. 봇이 "연결되었습니다"라고 답하고, 사이트의 텔레그램 항목이 **연결됨**으로 바뀝니다. 몇 초 걸립니다.

> 다른 텔레그램 계정으로 바꾸려면 **연결 해제**를 누르고 새 코드를 다시 보내면 됩니다. **텔레그램 테스트**로 메시지가 오는지 확인할 수 있습니다.

### 4. 관리자 승인 기다리기

가입 직후에는 **거부** 상태라 조회 버튼이 눌리지 않고 화면 위에 "관리자 승인 대기 중" 안내가 뜹니다. 관리자가 허용하면 바로 풀립니다. 화면은 30초마다 자동으로 상태를 확인하니 새로고침하지 않아도 됩니다.

승인 전에도 2번(코레일 계정)과 3번(텔레그램 연결)은 미리 해 둘 수 있습니다.

### 5. 기차 빈자리 조회

**기차** 탭에서 합니다.

1. **출발역**과 **도착역**을 고릅니다. 주요역이 위에, 나머지 역이 가나다순으로 아래에 있습니다. 가운데 **⇄** 버튼으로 두 역을 바꿀 수 있습니다.
2. **열차 종류**는 기본이 전체입니다. KTX 만 보려면 KTX 를 고릅니다.
3. **출발일**과 **시작·종료 시간**을 정합니다. 하루 전체를 보려면 **하루 전체 시간**을 체크합니다.
4. 왕복이면 **왕복**을 체크하고 오는 편 날짜와 시간을 넣습니다. 오는 편은 역이 자동으로 뒤바뀝니다.
5. **조회**를 누르면 결과가 화면에 뜨고, 같은 내용이 텔레그램으로도 전송됩니다.

결과 카드는 접혀 있고 제목 줄에 "N편 중 빈자리 M편"과 빈자리 열차 요약이 보입니다. 제목을 누르면 전체 표가 펼쳐지며, 열차마다 일반실·특실이 **가능**인지 **매진**인지 표시됩니다.

> 오늘 날짜를 조회하면 이미 지난 시각의 열차는 자동으로 빠집니다. 직통 열차가 없는 역 조합은 "조건에 맞는 열차가 없습니다"로 나옵니다.

### 6. 기차 감시 등록 (취소표 잡기)

원하는 열차가 매진일 때 씁니다. 조건을 등록해 두면 서버가 **2분마다** 다시 조회해서, 매진이었다가 빈자리가 생긴 열차를 텔레그램으로 알려 줍니다.

1. 5번과 같은 방법으로 조건을 맞춥니다. **알림 대상 좌석**에서 일반실만, 특실만, 둘 다 중 하나를 고릅니다.
2. **이 조건 감시 등록**을 누릅니다. 왕복이면 가는 편·오는 편이 각각 등록됩니다.
3. 아래 **감시 목록**에서 상태, 마지막 점검 시각, 결과("76편 조회, 빈자리 3편" 등), 알림 횟수를 볼 수 있습니다.
4. 필요 없어지면 **중지** 또는 **삭제**. 출발일이 지나면 자동으로 종료됩니다.

> **동시에 켜 둘 수 있는 감시는 2건까지**입니다(중지한 것은 제외). 왕복 하나가 2건입니다. 더 필요하면 관리자에게 요청하세요. 서버 전체가 코레일 계정 하나처럼 보이기 때문에 감시가 많아지면 모두의 계정이 위험해집니다.

### 7. 알림이 오면

메시지는 이런 모양입니다.

```
🚄 빈자리 발생: 서울 → 부산 2026-09-25
- KTX 013  07:27→10:03  일반실 O / 특실 X
- KTX-산천 101  08:08→11:16  일반실 O / 특실 O
예매: https://www.korail.com
```

- 알림은 **새로 빈자리가 생긴 열차**가 있을 때만 옵니다. 계속 비어 있는 열차는 다시 알리지 않습니다.
- 등록 직후 첫 점검에서는 그 시점에 비어 있는 열차 전부를 한 번 알립니다.
- 이 서비스는 **예매를 대신하지 않습니다.** 알림을 받으면 바로 코레일톡 앱에서 직접 예매하세요. 취소표는 몇 분 안에 사라지는 경우가 많습니다.

### 8. 공연 취소표 (NOL 티켓)

콘서트·뮤지컬 등 NOL 티켓에서 파는 공연의 잔여석을 봅니다. 코레일 계정과 무관하며, 관리자 승인만 있으면 됩니다.

1. **공연** 탭에서 공연명·아티스트·장르(예: `적재`, `뮤지컬`)를 넣고 **검색**. 아래 "진행 중인 공연 보기" 버튼(콘서트·뮤지컬·연극…)을 누르면 지금 판매 중인 공연이 바로 나옵니다. NOL 상품 주소나 상품코드를 그대로 붙여 넣어도 됩니다. 기본은 **판매 중**인 공연만 보이며, 아직 티켓이 열리지 않은 공연은 "판매 예정 공연도 포함"을 켜면 나옵니다.
2. **공연** 드롭다운에서 고르면 장소·공연 기간·예매 마감이 보이고, **관람일**에 남은 공연일이 채워집니다(안내문에 시각이 있으면 함께 표시).
3. 관람일을 고르고 **조회**하면 그 날짜의 회차·등급별 잔여석이 표로 나옵니다. "남은 기간 전체 조회"는 하루씩 조회해 이어 붙이므로 최대 14일까지만 봅니다.
4. 조회 뒤 **회차**와 **알림 대상 등급**을 좁힐 수 있습니다. **이 조건 감시 등록**을 누르면 감시 목록에 🎫 로 표시됩니다. 감시는 관람일 하루 단위이며 공연 감시 상한(기본 2건, 기차와 별도)을 씁니다.
5. 매진(0석)이었다가 잔여가 생기면 이런 알림이 옵니다. 관람일이 지나면 자동 종료됩니다.

```
🎫 취소표 발생: 2026 적재 LIVE SESSION : in s c ap e 2026-09-18
- 004회차 전석  잔여 2석
예매: https://nol.yanolja.com/ticket/products/26011367
```

> 취소표는 미입금 자동취소가 몰리는 새벽 0~2시와 오전 9시 전후에 많이 나옵니다. 잔여 1~2석은 몇 초 안에 사라지므로 알림을 받으면 바로 NOL 앱에서 예매하세요. 감시 1건은 주기마다 NOL 호출 1회를 씁니다.

### 9. 자주 묻는 질문

- **조회 버튼이 눌리지 않아요.** 관리자 승인 전입니다. 기차 조회는 코레일 계정 등록도 필요합니다. 화면 위 상태줄의 빨간 점을 확인하세요.
- **"아이디 또는 비밀번호가 올바르지 않습니다"가 떠요.** 코레일 계정 정보가 틀린 것입니다. 코레일톡 앱에서 로그인이 되는 정보인지 확인한 뒤 내 설정에서 다시 저장하세요.
- **텔레그램이 연결되지 않아요.** 코드를 보내기 전에 봇에게 먼저 시작(또는 아무 메시지)을 보냈는지, 코드 6자리를 정확히 보냈는지 확인하세요. 화면의 코드가 바뀌었으면 새 코드를 보내야 합니다.
- **알림이 너무 자주 와요.** 출발이 임박한 인기 노선은 취소표가 계속 나와서 그렇습니다. 시간 범위를 좁히거나 좌석 종류를 한정하면 줄어듭니다.
- **내 코레일 비밀번호는 안전한가요?** 서버에 암호화되어 저장되고, 조회할 때만 코레일 로그인에 사용됩니다. 화면이나 다른 사용자에게 보이지 않습니다. 그래도 걱정되면 언제든 내 설정에서 지우거나 바꿀 수 있습니다.
- **주의.** 이 서비스는 코레일 공식 서비스가 아니며, 코레일 정책이 바뀌면 예고 없이 멈출 수 있습니다. 개인적으로 쓰는 용도로만 이용해 주세요.

## Lightsail 배포

서울 리전 Ubuntu 인스턴스에 systemd 서비스로 올리고, 기존 Caddy 가 HTTPS 를 붙입니다. 설정 파일은 `deploy/` 에 있습니다.

- 최초 1회 (인스턴스에서): `sudo bash deploy/setup-server.sh <도메인>`. 이미 Caddy 가 있으면 이 스크립트 대신 `/etc/caddy/Caddyfile` 에 아래 블록만 추가하고 `sudo systemctl reload caddy`.

```
rail-watcher.duckdns.org {
    reverse_proxy 127.0.0.1:8000
    encode gzip
}
```

- 코드 갱신 (이 PC 에서): `.\deploy\deploy.ps1 -HostName <인스턴스 IP>`. 서버의 `.env` 와 `data/` 는 유지됩니다.
- 서비스는 `TZ=Asia/Seoul` 로 실행되며, 코드도 한국 시간 기준으로 동작합니다.
- 로그: `sudo journalctl -u rail-seat-watcher -f`

## 구조

```
app/
  config.py          .env 로딩, 서버 암호화 키
  crypto.py          코레일 비밀번호 암복호화, 앱 비밀번호 해시
  users.py           사용자/세션 저장(data/users.json, data/sessions.json)
  korail_service.py  pykorail 래퍼 (사용자별 세션, 서버 전체 직렬화, 하루 전체 페이징 조회)
  nol_service.py     NOL 티켓 공연 검색·상품 요약·날짜별 잔여석 (로그인 없음, 서버 전체 직렬화)
  call_stats.py       사용자별 누적 조회 횟수(data/call_stats.json, 재시작에도 유지)
  telegram.py        텔레그램 발송(chat_id 별) + 연결 코드 수신 폴링(getUpdates)
  watcher.py         감시 조건 저장(data/watches.json) + 폴링 루프 (kind: korail / nol)
  main.py            FastAPI 라우트
  static/login.html  로그인/가입 화면
  static/index.html  조회/감시 화면
```

## API

모든 `/api/*` 는 로그인 쿠키가 필요합니다(인증 API 제외).

| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/auth/register` | 가입 (username, password, invite_code) |
| POST | `/api/auth/login` / `/api/auth/logout` | 로그인 / 로그아웃 |
| GET | `/api/me` | 내 정보 |
| PUT | `/api/me/settings` | 코레일 아이디/비밀번호 저장 |
| POST | `/api/me/korail/test` | 코레일 로그인 테스트 |
| POST | `/api/me/telegram/unlink` | 텔레그램 연결 해제(새 코드 발급) |
| POST | `/api/telegram/test` | 내 텔레그램으로 테스트 발송 |
| GET | `/api/admin/users` | (관리자) 사용자 목록 |
| PUT | `/api/admin/users/{id}` | (관리자) 허용/거부, chat_id, 기차·공연 감시 상한, 감시 주기 변경 |
| DELETE | `/api/admin/users/{id}` | (관리자) 사용자와 감시 삭제 |
| GET | `/api/stations` | 역 목록(주요역/전체) |
| POST | `/api/search` | 즉시 조회(왕복은 화면에서 2회 호출) |
| GET | `/api/nol/search?q=&upcoming=` | NOL 공연 검색(판매 중, upcoming=1 이면 판매 예정 포함; 상품코드/주소도 가능) |
| GET | `/api/nol/goods/{code}` | NOL 상품 요약(장소, 공연 기간, 예매 마감, 날짜별 시각) |
| POST | `/api/nol/remaining` | 관람일(또는 남은 기간, 최대 14일) 회차·등급별 잔여석 |
| POST | `/api/watches/nol` | 공연 감시 등록 (goods_code, date, play_seq, grades) |
| GET/POST | `/api/watches` | 내 감시 목록 / 기차 감시 등록 |
| POST | `/api/watches/{id}/toggle` | 감시 중지/재개 |
| DELETE | `/api/watches/{id}` | 감시 삭제 |
| POST | `/api/watches/run-now` | 내 감시를 지금 한 번 점검 |
| GET | `/api/status` | 로그인/설정/마지막 점검 상태 |
